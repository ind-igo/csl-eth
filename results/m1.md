# Milestone 1: a mainnet slice at one finalized root, complete query acquisition

Run 2026-10-30 to 2026-11-01. The plan is `wiki/projects/cold-state-layer/specs/poc-ethereum.md` in the vault, section "Milestone 1"; the reasoning behind each step is in `docs/decisions.md`. The question milestone 1 asks: can a client acquire a complete proof of any account, slot or absence from path-keyed static pages in one speculative round, within a budget a wallet can use, and establish absence from the trie alone for every shape of miss, on mainnet's own state with no node anywhere.

It can. Every exit rule passes on a 1/4096 slice of mainnet at block 26,311,778, read through the finalized head from one checkpoint, served by R2. The rules that need the full state (model size, memory at scale) are met on the slice and by construction, and are measured for real in milestone 4.

## The setup

- **State.** Prefix `1a7` (1/4096 of the account trie), fetched over devp2p `snap` from mainnet peers at the epoch-boundary block 26,311,778 (hash `0x1a19…4af7`, state root `0xe255…335c`). Every range came with a boundary proof, and the slice's account subtrie rebuilds through 102 sealed ancestors to the header's `state_root`: the expected values are the network's state at that block, proven at fetch time.
- **Head.** `head/` holds the beacon light-client bootstrap, the period update and the finality update that names the block, verified by the client from checkpoint root `0xe59d…cf0b` (500 of 512 sync-committee signers).
- **Bucket.** Four tables in csl-run's variable layout with paged models (format 2), plus 408 code blobs: account nodes, storage nodes, code, and the same nodes content-addressed for the baseline. Public R2 bucket `csl-eth-apac`.
- **Client.** `csl-eth-client`, sans-I/O, `--prefetch 1 --top-levels 4` unless stated. The same client runs as wasm in the deployed page, https://csl-eth.indigo-db8.workers.dev.
- **Commands.** `csl-eth workload` (the workload, `crates/snap/src/workload.rs`) and `csl-eth faults` (the fault table, `crates/snap/src/faults.rs`). Their reports are `results/m1-workload-local.json`, `results/m1-workload-r2.json` and `results/m1-faults.json`.

Locally the same draws at 10,000 per kind give the same requests, bytes and rounds to the first decimal. Two things stand out:

- **Repairs almost never cost a round.** Leaves below the speculated depth and walks through an extension need a node the speculative round did not ask for, but the page either side of each predicted page is already in the round, so the repair finds it there. One account read in 500 on R2 took a second round, for a cold model page.
- **Storage is the expensive read, and it is speculation, not depth.** Every slot read costs about 132 KB, even for an account with empty storage, because the storage trie's pages are fetched in the account's round before the account says whether it has storage. That buys one round instead of seven to ten. The 50 KB rule is an account rule; the plan's open question on storage speculation depth (measure the depth distribution, then fix the default) now has its distribution: storage leaves in the slice reach depth 6, and half the present slots are at depth 4 or more.

## Fault table

`csl-eth faults` serves corrupted responses through a faulting driver. A clean walk first records each read's nodes; each aimed fault then corrupts only the page holding one chosen node per read, cycling through the account trie's depths, every storage depth and the code table in path mode, and the matching hash-table entries in baseline mode. 892 path-mode and 850 baseline reads per fault, scored by the workload's scorer, with a control row that must be all correct.

The table passes only if it is **safe** and **exercised**. Safe: the control row is all correct and no row has a false answer. Exercised: every fault changed responses in every mode it applies to, found a node to aim at on at least 98% of the reads it was not told to spare (50% for the two fence faults, which skip pages whose fences are already exact), and landed on at least 98% of its aims within each table. A run at fault rate 0 is safe and fails. On the slice every aim landed; the one pair that does not apply is `truncated_blob` in the baseline, which reads no code.

No row produced a wrong value, a false absence, a false presence or an answered outside key. The correct answers under faults are the 50 outside keys (whose right answer is `Insufficient`), reads the fault could not reach (a fence that cannot misroute an exactly predicted page, bit flips in padding the reader never reads) and reads that re-located a shifted page by its fences and verified it, which is the plan's "correct answer from a repair fetch". A Bloom filter is not part of this format, so the plan's "zeroed Bloom" has no row.

Three things the table shows about the design:

- **The manifest's per-table file hash is informational.** The client never checks it: values are proven by the trie and the model by `model_root`, so a mirror serving different run files under the manifest is caught node by node, not at open. Checking it would cost reading every file whole.
- **Narrowing a fence cannot misroute a read.** Every node a walk needs is an entry, and narrowed fences still cover every entry; a forged fence hurts only by widening (caught as `Missing`, never absence) or by excluding a held key (caught at decode). Many pages have nothing to narrow: in the pre-order account table a node's first child has its parent's key plus one, so a page that ends on a node and its first child already has exact fences.
- **A host that shifts ranges by a page breaks path-keyed reads safely and the baseline barely.** The root's key pins it to page 1, which a shifted host never serves, so path mode reports a fence gap; a hash key lands anywhere and the fence walk steps to the real page.

## What milestone 1 does not show

- **The oracle.** The plan scores answers against `eth_getProof` at the pinned block. The workload implements it (addresses from recent blocks whose hash falls in the prefix, compared field by field), but every free public endpoint refuses a proof 7,000 blocks back. The expected values are instead proven to `state_root` by the peers' range proofs at fetch time, which is independent of our producer. Scoring by the oracle needs a run within about 128 blocks of a fetch, or an archive key.
- **Full-state behaviour of the model.** Each slice table is one model page, so the top model's fan-out over the 2,700 model pages the account table would have at full state is exercised only by csl-run's synthetic tests. Milestone 4's full export measures it, with the cold-read model-page count on mainnet shapes.
- **Memory and download at full state.** Both rows pass by construction; neither has been measured beyond the slice.
- **The head under faults.** Head fault injection is milestone 2's.
