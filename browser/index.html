FAQ

What is this?

A demo. All of Ethereum mainnet's current state (every balance, every contract's storage, all contract code) is published as plain files in a cloud storage bucket. This tab reads those files directly and proves each answer is correct. There is no RPC provider, API or Ethereum node behind it.

Why does it matter?

Wallets and apps usually read Ethereum through an RPC provider and trust its answers. Here nothing that serves the data is trusted: the bucket is only a file host, and anyone could mirror it. Reading the chain needs no generous node operator, only somewhere that serves bytes.

How does the tab know the answer is right?

It starts from one trusted checkpoint and follows the beacon chain's light-client data to the latest head, which must be signed by at least 342 of the 512 validators in the sync committee. Every value it reads is hashed up to the state root in that signed head. A wrong or missing byte makes the read fail rather than return a wrong answer. Tick "tamper next read" to watch it refuse a flipped byte.

How up to date is it?

By default, about 35 seconds behind the latest block. That block is signed but not yet final, so in rare cases it could still be replaced. Add ?tier=finalized to the address to read only finalized blocks, about 13 minutes behind.

Who keeps the files current?

A small server with no Ethereum node. For each new block, it asks mainnet peers for the parts of the state that changed and uploads them as a small update file. Running it and storing everything costs under $40 a month. In a real deployment, an Ethereum node would publish these updates as a side effect.

What am I looking at?

Left: the chain of trust, from the checkpoint to the state root. Middle: the path through Ethereum's state trie that proves this answer. Right: every 4 KB page in the bucket, with the ones this read fetched lit up. Bottom: each network request, on the real clock.

What can't it do yet?

Run contract calls (eth_call), read transaction history or logs, read past states, or send transactions. This demo shows the hard part: current state, read and verified by a small light client from plain files.
